# 平面图烘焙（大地图 / M 键的数据源）

> 2026-09-15 建立。目标：把 3D 地图离线烘成俯视平面图，供大地图（M 键）与"多图拼成世界图"使用。
> 现状：管线已跑通，fore-1 / village-2 两张与**原版 A 族缩略图**逐特征吻合（朝向、取景、地标位置全对）。

## 一、产出与约定

```
npm run bake-maps -- --maps=2,3 --scale=8
npm run bake-maps -- --all --scale=8
```

产物落 `<VITE_ASSET_ROOT>/image/planemap/`（默认，可用 `--out=` 改）：

| 文件 | 内容 |
|---|---|
| `<mapId>.png` | 该图的平面图（RGBA，图外透明） |
| `index.json` | 元数据：比例尺、图幅、AABB、装饰数、耗时、备注 |
| `_bake.log` | 逐步日志（含运行时 `console.warn` 与未捕获错误） |

**约定（世界图能直接拼的前提）**：

- **统一比例尺**：1 像素 = `scale` world 单位。**图幅 = ceil(AABB / scale)**，即"出图多大取决于地图多大"，
  与地图本身尺寸无关 —— 所有图的像素坐标与世界坐标是同一个线性映射。
- **当前产物 = `1px/16` + WebP**（玩家下载量优先，2026-09-15 定）：63 张合计 **2.95 MB**
  （最大单张 196 KB、中位 41 KB、图幅中位 528×557）。改一版只要换两个参数重跑（见下表）。

  | 配置 | 63 张合计（实测外推） | 说明 |
  |---|---|---|
  | 1px/8 PNG | ~99 MB | 最初那版；下载量最大 |
  | 1px/8 **WebP** | ~10 MB | 与最初观感相同，体积 1/10 |
  | **1px/16 WebP** | **2.95 MB** | **当前产物** |
  | 1px/4 WebP | ~40 MB | 比最初还清（2×） |
  | 1px/4 PNG | ~400 MB | 不建议 |

  实测：地形是高频细节，**WebP 相对 PNG 小约 10 倍**（`ALPH` 通道保留，水面透明不丢）。
  所以"太清晰/太大"这两件事可以分开调：要小就 `--scale=16 --format=webp`，要更清就 `--scale=4 --format=webp`。
  改完**页面不用改代码** —— 比例尺与扩展名由 `index.json` 提供（`?scale=`/`?format=` 可临时覆盖）。
- **朝向**：东 = +X 在右，北 = −Z 在上；**像素 (0,0) ↔ world (minX, minZ)**（西北角）。
  与场内小地图、原版 A 族 `field/map/*.tga` 同向。
- **取景**：AABB 取整到整像素，比例尺严格等于 `scale`（不走样）。
- **观感**：复用运行时 `loadMap` / `loadMapDecor`（同一套几何、贴图、装饰摆放），
  环境光取白天默认值（`uEnvLight` 全 0 = DarkLevel 0）、无火把、无场景灯、**距离雾关闭**。
- **图外透明**：背景 alpha=0。

## 二、四个坑（都是实测踩出来的，改前先读）

1. **`OrthographicCamera` 的 left/right/top/bottom 是"相对相机位置"的，不是世界坐标。**
   相机放在取景框中心时若把绝对坐标塞进去，等于偏移算两次 —— 整张图被推出画面，
   表现是"draw call 有、一个像素都没有"。正确写法：对称的半宽高 + 相机放中心。
2. **必须调用 `MapRenderer.render(camera)`**（运行时的**每帧**入口，见 `WorldView` 渲染循环）。
   它做分格剔除 + 索引打包（`setDrawRange`）；不调的话几何索引缓冲还是全 0（退化三角形），
   同样表现为"提交了几万个三角面但画不出东西"。调用前要先把 `camera.matrixWorldInverse` 算好
   （它读这个矩阵做视锥判定）。
3. **距离雾必须关**（`mapRenderer.setFogRange(0, 0)`）。那是给第三人称的距离雾
   （2400~3000 world 单位就全黑），俯视正交相机必然在 2km 外 —— 不关整张图全黑。
   `uFogRange` 现在是 uniform，**所有材质共享同一个 `Vector2` 实例**（`userData.shader` 要等首帧才存在，
   所以"改已编译 shader 的 uniform"这条路在烘焙时是空转）。
4. **PT 的贴图/顶点 alpha 在原引擎里不参与合成**（游戏画布不透明，alpha 被忽略）。
   烘图要 alpha 通道，所以烘焙会给每个材质补一句 `gl_FragColor.a = 1.0`（只影响本次烘焙）。
   不补的表现是"有颜色但整张全透明"，与"没画"在像素上无法区分。
   另外无头模式下**从不进 DOM 的 WebGL canvas 用 `drawImage`/`toBlob` 取不到像素**，
   读回一律走 `gl.readPixels`。

判据：**可见像素为 0 = 失败**（不产出文件、记 `_bake.log` 与 `index.json` 的 notes）。
序号外的 note 还会记：装饰缺失数、AABB 与 `fields.json` 的偏差（> 1 world 单位时）。

### 2.1 材质剔除/保留（`src/tools/planemap-exclusions.ts`）

大片水面/背景板在平面图上要么盖住地形、要么没有意义，但**一条通用判据做不对**，实测结论：

- **默认规则**：剔**引擎水面**（`windMeshBottom & 0x7FF == 0x200`）。
- **必须按贴图名整组剔**：一个水面常由**多层材质**组成、只有一层带那个标记
  （`#17 morion1` 实测：`sea_0.BMP` 两层，只剔带标记的那层会留下"残影"）。
- **整片非水材质**（`#28 iron-2` 周围那片黑液 = 原版缩略图里画成青色水纹的背景板）没有水面标记，
  只能逐图指认。
- **有些水必须保留**：`#10 desert2` 沙漠中的水源（绿洲）、`#34 greedy` 整张图就是那座湖 ——
  剔了图上就看不出是水（用户 2026-09-15 看图后指定）。

所以做成**逐图逐贴图的覆盖表**（键取贴图名而不是 `matIdx`：matIdx 是数组下标，smd 一改版就变；
比对用 basename，因为 smd 里存的是全路径）。当前条目：

| 图 | 贴图 | 动作 | 依据 |
|---|---|---|---|
| #10 desert2 | `wa01.bmp` | keep | 沙漠中的水源（绿洲），剔了中心就是空的 |
| #34 greedy | `sea_0.bmp` | keep | 整张图就是这座湖 |
| #28 iron-2 | `irk036.bmp` | hide | 周围整片"黑液"背景板 |

**怎么看"这块该不该留"**：把我们的烘焙与原版 A 族缩略图（`client/field/map/<名>.tga`）并排比 ——
原版那张是它自己烘的，同一块区域它画成什么，一眼就能判断我们该保留还是剔除
（`#28` 就是这么定位的：我们全黑、原版是青色水纹）。
新增条目**必须写 `note`**（依据），`--dumpMaterials` 可打出材质表（贴图/占图幅/高度区间/混合与水面标志）。

自检：`#[N] 材质策略:` 会逐图记下"剔除几组、显式保留几组、各组是什么"，出问题时看这行就够。

### 2.2 集合一致性（index.json 是**整个集合**的元数据）

- 每轮日志独立命名 `_bake-<runId>.log`，并在最后写 `_bake-<runId>.done.json`
  （`{ok, failed, requested, bakedIds, failedIds}`）—— 脚本按它**验收**：请求的图必须全部烘出来，
  否则报失败退出。**不拿 `index.json` 当完成信号**（它开跑前就存在 → 会把上一轮当本轮结果、静默报"成功"），
  也不靠日志尾行（长时间运行下会丢）。
- **一致性闸门**：开跑前读现有 `index.json`，若它的 `scale`/`format` 与本次不同 → **拒绝写入**并说清
  （混合比例尺/格式会毁掉"所有图同一坐标映射"这个前提）。同参数则**合并**记录（单张重烘不会截断集合）。
- 日志用"内存累积 + 整份重写"而**不是逐行 append**：实测长时间运行下页面侧的多次 append 会静默丢，
  日志只剩开头几行。
- 卡死看门狗：120 s 内日志无增长 → 判定卡住并报出最后一行；单图加载另有 90 s 超时
  （无头下 worker 解析偶发不返回，超时把它变成一条可见失败）。

## 三、验证状态

- **fore-1、village-2 与原版 A 族 `field/map/*.tga` 并排比对：布局、朝向、地标位置全部吻合**
  （fore-1 的中心石台/环形遗迹/断柱，village-2 的广场/码头船/水池）。分辨率是 A 族的 4 倍（scale=8）。
- `AABB` 与 `fields.json` 的 `bounds` 偏差 = **0**（两源同源，交叉核对通过）。
- 副产物发现：**village-2 有 4 个装饰在运行时就是缺的**（`forest\v_ani01..04.ASE`，
  `decorSmdPath` 反查表里没有对应 .smd）→ **游戏里同样缺**，属既有数据缺口。

## 四、待定（观感决策，未做）

1. **亮度**：烘焙=游戏内正午观感（`uEnvLight`=0），比原版 A 族缩略图明显偏暗。
   要更"地图感"可以给烘焙加一个环境光偏移（`setEnvLightOffset` 之类）或后处理提亮 ——
   需要定一个值并记依据。
2. **水面**：海面在俯视图上是一整片平铺的滚动贴图，观感偏"糊"。
   可考虑烘焙时把水面压成单色（地图风格化），或在 UI 层叠一层。
3. **装饰是纯色**（运行时材质逆向尚未做，`0x88aa44`），所以建筑现在是绿色块而不是贴图 —— 与游戏内一致。
4. **多层洞穴**：俯视会把多层压平（原版干脆写"no guide map"）。要不要按高度分楼层，未定。

## 五、地图等级门槛（名字后面的括号）

`npm run map-levels` → `src/maps/map-levels.generated.json`，大地图在每张图名字后显示 `（N）`。

- **数据源**：`deploy/postgres/init/gamedb.sql` 里 `COPY gamedb.maplist` 的导出段
  （`id, name, shortname, typemap, levelreq, pvp, stagefile`）。**`maplist.id` 就是 mapId**
  （逐条核对过：0=Acacia Groove/fore3、3=Ricarten/ric、11=Battlefield of the Ancients/desert3）。
- **规则**：`levelreq` 为 **0 或 1 = 无实质限制**（PT 角色从 1 级起），**只有 > 1 才在名字后加括号**。
  63 张里 43 张有门（森林/村庄那类都是 1）。生成器会打印全部有门的图，便于核对。
- **与运行时同源**：客户端进图快照本来就带 `levelReq`（`S2C_EnterGame.maps[].levelReq` →
  `src/game/safeZones.ts`），游戏里用的是同一份数；demo 没有游戏会话，所以走静态这份。
- 生成器自检：63 张图必须**全部**在 maplist 里找得到，缺一张就报错退出（不拿默认值糊过去）。

  复制一遍，早晚与游戏漂移。
- 编排脚本 `scripts/bake-maps.ts`（起 dev server + 生成作业页 + 无头 Chrome + 轮询产物 + 收尾），

  `--format=webp|png` / `--quality=` / `--scale=` / `--out=` 同理。
  ⚠ 它会**自动挑空闲端口**、每次用**独立 Chrome profile**（固定名字会被上一次没退干净的进程占住，
  表现为"浏览器提前退出 code=21"），并在开跑前清掉上次的 `_bake.log` 与 `index.json`

## 六、大地图 demo（世界 → 区域 → 地图）

- **组件本体在 `src/ui/WorldMap.ts`**（游戏与调试宿主共用同一份实现；API/接线见 `docs/worldmap.md`）。
  页面 `worldmap.html` + `src/tools/worldmap-demo.ts` 只是宿主：URL 带状态、`?selftest=1` 跑 54 条断言。
- **数据只有一套**：已烘的平面图（统一比例尺、像素 (0,0) ↔ AABB 西北角），
  所以任何一层都是"按世界坐标把若干张图摆上去 + 决定看哪一块"，不需要为每层各做资产。
- 层级（判据见 `src/maps/planemap-regions.ts` 顶部）：
  · **世界图（大陆）不分区**（用户 2026-09-15 定：*"大陆分区域是个很傻的行为，应该直接每个地图
    可以单独点击查看"*）—— 世界图上**每张地图单独可点**，点进即那张图（世界 → 地图 两级）。
    大陆成员 = 原版给了独立 guide-map 贴图的那 26 张，实测两两包围盒间隙 ≤ 200 world 单位、拼起来无缝。
  · **世界图之外的 37 张**（副本/洞窟/竞技场/新区域）在世界坐标上要么与野外图重叠
    （`ba2`/`seab` 重叠 95%），要么被丢在很远的地方 —— 它们不上世界图，按家族/类型分组从左栏进入；
    组视图把该组成员**按世界坐标平铺**（同家族楼层本来就是并排摆的：古代监狱两两间隙 ≤ 8.6k、
    诅咒神殿 ≤ 2.0k，实测），再点进单图（世界 → 家族 → 地图 三级）。家族划分由用户指定。
  · **地图** = 单张平面图，邻图压暗作背景。
- 交互：左键下钻、右键/`Esc` 上升、滚轮缩放（以光标为锚）、拖拽平移、面包屑可点。
- URL 带状态便于分享/截图：`?level=0`、`?level=1&region=ice`、`?level=2&map=3`、`?scale=8`。
- **自检**：`?selftest=1` 走一遍状态机（世界点森林→区域、区域内点图→地图、两级上升、
  四个副本家族"平铺处点击进该层"、世界图不含非大陆地图、区域表完整性 —— 15 条），
  结果写进 DOM/console，无头浏览器可直接读。
- 已知观感项（未处理，见 §四）：洞窟偏暗（顶点色本身就是暗的）、
  虚空类地图（贝拉塔/黑暗圣殿等）底下一整块**不透明黑平面**，在世界图上是黑方块。
